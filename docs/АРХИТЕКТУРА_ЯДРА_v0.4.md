## 1. Что это и где граница

Ядро — общий язык данных шести продуктов (TechSense, Конфликтология, Web Monitoring, Dossier Analyser, Compliance Check, SemanticWiki). В v0.4 три исполняемые части:

1. **Онтология 0.2.3** — JSON Schema, реестр предикатов, единственный нормативный валидатор, эталонный мир на все шесть продуктов, 291 вектор, 251 мутант.
2. **Срез на PostgreSQL 16** — правила онтологии как ограничения и триггеры базы; ключи идентичности база вычисляет сама; живая роль приложения имеет минимальные права; каждое правило атакуется в обход валидатора.
3. **Проекции S3** — досье, отчёт Проверки и провенанс строятся прямо в базе, выдаются только по допуску, каждое предложение ведёт к фрагменту источника.

Пока нет: адаптера TechSense (S4), объектного хранилища и публикаций WM (S5), идентификаторов СНГ (S6), выдачи досье в .docx, ролей пользователей в интерфейсах. План и участие людей — `АС_ПЛАН-ГРАФИК_2026-10-01_v001.md`.

Правило проекта: **правило без кода и без негативного вектора правилом не считается; условие, ослабление которого не ловит ни один вектор, считается непроверенным; правило, заявленное «в базе», должно выдерживать атаку в обход валидатора; правило о времени и закрытости должно выдерживать гонку двух транзакций.**

## 2. Решения

| № | Решение |
|---|---|
| D1 | Онтология и данные — первый слой. CM18 заморожен как справочный документ слоя доверия. |
| D2 | Утверждение отдельно от сущности. Сущность хранит только идентичность; всё остальное — утверждения с доказательствами до байтового фрагмента источника. |
| D3 | Адресация по содержимому: `source_id` = sha256 байтов; `claim_id`, `receipt_id` = sha256(RFC 8785 JCS), целочисленный профиль. |
| D4 | **Одна сущность в проекте — строго один раз.** Точный ключ (NFC, свёртка ширины, без невидимых, casefold, тире → «-», без кавычек) и скелет. **v0.4:** скелет дополнительно снимает комбинирующие ударения (кроме бреве и диэрезиса — й и ё остаются буквами) и сводит к кириллице латинскую ë, лунную сигму, армянскую օ, капители и двойников из письма чероки; пробел Брайля невидим. Ключ тега оборудования хранит границы групп: «К-1/12» ≠ «К-11/2», но «Н-101» = «Н101» = «н 101». Ключ модели — без NFKC («ЦНС 10²» ≠ «ЦНС 102»). |
| D5 | Проверка — самостоятельный объект. Статус утверждения берётся на момент завершения. **v0.4:** предыдущая Проверка должна быть завершена до запроса новой и не шире её по маркировке; строки закрытой Проверки (итоги, утверждения, следы поиска) принимаются только в транзакции, которая её закрыла; в отменённую — никогда после отмены. |
| D6 | Маркировки: производное не шире ни одного входа. **v0.4:** маркировка — строго {level, categories} с известными значениями (CHECK на каждом столбце маркировки); доминирование fail-closed; слияние в сущность с более широкой маркировкой запрещено. |
| D7 | Receipt подписывается Ed25519; ключ — только из доверенного реестра своего tenant. |
| D8 | **Разделение валидатора и базы (v0.4):** только валидатор — JCS-адреса и подпись, строгая схема и представление чисел JSON (1e2 и 100 в jsonb неразличимы), байты источника против адреса при загрузке; всё остальное держит и база: ключи и скелеты (таблицы символов **сгенерированы из валидатора**), контрольные суммы, квалификаторы по реестру, календарные даты, схемы идентификаторов и единицы, границы проекта и tenant, неизменяемость, системное время, доказательства по байтам, маркировки, правила Проверки, привязка receipt. |
| D9 | Fail-closed: фаза 0 итеративна с пределом вложенности 64; исключение не превращается в «прошло». |
| D10 | Противоречие источников — предупреждение. |
| **D11** | **Решения аналитика об идентичности** — запись `IdentityDecision`, append-only, с автором и системным временем: `DISTINCT` (совпадение скелетов — разные сущности; слить их после этого нельзя) и `QUALIFY` (однократное добавление недостающего disambiguator или места к существующей сущности со слабым ключом). Омоним, заведённый раньше уточнения, остаётся дублем. |
| **D12** | **Возможный дубль — ошибка на уровне базы.** Совпадение скелетов без решения `DISTINCT` или без различающих пометок отвергается при COMMIT (`POSSIBLE_DUPLICATE`); загрузчик отказывает раньше. |
| **D13** | **Печать истории.** После импорта история запечатывается (`ac.history_seals`); исторический режим (только сессия-член `ac_migrator`) пишет лишь позже печати; рецензия не может встать задним числом под закрытую Проверку, которая опирается на это утверждение. |
| **D14** | **Сериализация записей, от которых зависит закрытая Проверка.** Рецензии, слияния и выводы из оборота, строки Проверки, наблюдения источников и закрытие Проверки берут консультативные блокировки в едином порядке (check < claim < entity < source); время таких записей читается после блокировки. Закрытие сначала берёт блокировку самой Проверки и только потом читает, на что она опирается. |
| **D15** | **Проекции только по допуску.** Читатель (`ac_reader`) не имеет доступа к таблицам; три функции проекций принадлежат не суперпользователю (`ac_projector`, только SELECT); допуск ищется по `session_user` в `ac_trust.clearances` (уровень и категории на проект, append-only, отзыв — пустым уровнем). Отказ всегда один и тот же: «ACCESS_DENIED: нет допуска» — без различия «нет» и «нельзя». |
| **D16** | **Невозвратность проекций.** Закрытая Проверка читается на момент закрытия: статусы утверждений, имена сущностей (слияния — только случившиеся к этому моменту), наблюдения источников (по времени поступления в систему). Досье — на момент `as_of`; будущее обрезается, последние 5 минут помечаются «предварительно». У каждой проекции digest (sha256 JSON), не зависящий от часового пояса сессии. |

## 4. Реестр правил: изменения 0.2.2–0.2.3

| Код | Изменение |
|---|---|
| ENTITY_DUPLICATE_IN_PROJECT | скелет v0.4 (D4); уточнение (QUALIFY) разделяет только то, что заведено после него |
| POSSIBLE_DUPLICATE | предупреждение валидатора; в базе — ошибка при COMMIT без решения аналитика (D12) |
| IDENTITY_DECISION_INVALID (новый, 36-й код) | «различны» для разных типов или слитых; уточнение сильного ключа, повторное, при наличии поля, для слитой к моменту решения |
| ENTITY_MERGE_INVALID | выжившая не шире маркировки сливаемой; слить признанных различными нельзя |
| CHECK_PREVIOUS_INVALID | предыдущая Проверка завершена до запроса новой |
| MARKING_BROADER_THAN_INPUT | Проверка не уже предыдущей Проверки |
| CHECK_CLOSED | строки закрытой Проверки — только в закрывающей транзакции |
| TEMPORAL_ORDER_INVALID | печать истории; рецензия под закрытую Проверку; поиск из будущего |
| QUALIFIER_INVALID, PREDICATE_RANGE_VIOLATION, IDENTIFIER_CHECKSUM_INVALID | теперь держит и база (D8) |

## 5. Проекции S3 (`slice/proj_s3.sql`)

| Функция | Что возвращает | Правила |
|---|---|---|
| `ac.dossier(project, entity, as_of)` | разделы по измерениям; в разделе — предложения, у каждого утверждения и фрагменты (цитата перечитана из байтов, verified); пустой раздел — «Сведений нет.»; расхождение источников по однозначному предикату — одним предложением с пояснением; объединённые карточки | видно только то, что доминирует допуск (утверждение, субъект, объект и то, во что они слиты); опровергнутое и отозванное исключено; только оспоренное фактом не подаётся |
| `ac.check_report(check)` | направления профиля по порядку: итог, риск, предложения, след поиска; «Не выявлено.» — только у завершённой Проверки и всегда со следом поиска; предыдущая Проверка — если читатель её видит | закрытая — на момент закрытия (D16); открытая и отменённая — черновик без риска |
| `ac.provenance(claim)` | текст, фрагменты, рецензии, receipt | допуск к утверждению и его сущностям |

`slice/render_s3.py` выводит проекции в Markdown по правилам оформления досье: только факты, источники после каждой главы (одна позиция на источник), даты ДД.ММ.ГГГГ, дата датированного факта жирным, без внутренних кодов и английских значений. Образцы: `slice/ПРИМЕР_ДОСЬЕ_S3.md`, `slice/ПРИМЕР_ОТЧЁТА_S3.md`.
