## 1. Что это и где граница

В v0.8 добавлен первый шаг решения D27 — **схема как данные**: tenant сам описывает свои классы, атрибуты, связи и
типы идентификаторов, и это описание — обычные записи ядра (с автором, временем, маркировкой, версиями), а не
таблицы и не код. Физическая модель при этом не меняется: ни одной таблицы на действие пользователя.

1. **Онтология 0.3** — три новых вида записей (`ClassDef`, `LinkDef`, `IdentifierDef`), десятый корневой тип
   сущности `THING`, литерал `CLASS_REF`, предикат `schema.is_a`, пространство предикатов tenant `x.…`;
   45 кодов ошибок (4 новых), 3 кода предупреждений (1 новый); 495 векторов, 418 мутантов.
2. **Срез на PostgreSQL 16** — `slice/ddl_s9.sql`: таблицы определений с версиями, замыкание иерархии, владельцы
   предикатов, страж утверждений по схеме своего времени, роль «Конструктора модели» `ac_modeler`, проекции
   «модель» и «пробелы схемы»; досье показывает классы и атрибуты tenant.
3. **Конструктор модели** — `core/model_constructor.py`: клиент реестра из командной строки (интерфейс — позже, в
   SemanticWiki; те же записи).
4. Всё из v0.7 без изменений; адреса всех 94 записей мира v0.7 (утверждения, источники, публикация, receipt) те же.

Пока нет: массивного профиля (D27.2–D27.4, цикл 10), внешнего профиля (цикл 11), миграций значений между версиями
схемы, идентичности сущностей по `IdentifierDef` (§8), реальных данных TechSense, Web Monitoring и ЕГРЮЛ.

## 2. Решение D27.1 как исполнено — и чем отличается от текста проекта

| № | Как сделано | Почему (и отличие от текста проекта D27.1) |
|---|---|---|
| D27.1-а | Определение — цепочка версий 1…n ключа `(tenant, id)`. **Запись журнала — часть каждой версии** (`change`: тип, описание, кто, когда). Отдельной записи `SchemaChange` нет; журнал — проекция над версиями (`ac.schema_journal`). | Отличие: в проекте — четыре вида записей. При отдельной записи журнала возможны определение без журнала и журнал без определения — оба случая нашла рецензия (S9R-17). Теперь их нельзя записать по построению. |

Заморожены: корневой тип, родитель, абстрактность, маркировка; у атрибута — тип значения, единица, схема; у связи — предикат, классы, кардинальность; у типа идентификатора — схема, корневой тип, приоритет, формат. Живая запись утверждения отвергается, если определение менялось после заявленного времени утверждения. | В проекте: «по системному времени записи, иначе задним числом можно выбрать старую схему» — исполнено; выгруженное из базы состояние проходит валидатор. |
| D27.1-е | `CLASS_REF` = ровно `{type, class_id}`: класс ищется в tenant проекта. Чужой класс неотличим от несуществующего. | Поля `tenant_id` и `label` из первой сдачи убраны: первое ни с чем не сверялось, второе выносило название класса в тело утверждения (S9R-09, S9R-24). |

## 3. Записи и правила

**ClassDef** — класс под одним из десяти корней: имя, родитель (того же корня, действующий, не шире по маркировке),
абстрактность, атрибуты `{predicate_id, name, value_type, cardinality, required[, unit][, scheme]}`.
**LinkDef** — связь: предикат `x.…`, класс-домен, класс-диапазон, кардинальность, симметричность (только внутри
одного класса). **IdentifierDef** — тип идентификатора для корневого типа: схема, сила, приоритет (один на корневой
тип), формат. **`schema.is_a`** — утверждение «сущность — экземпляр класса»: с доказательством и временем, как любое
другое; тип сущности остаётся неизменяемым корнем.

| Правило | Код |
|---|---|
| ключ определения `(tenant, id, версия)`; версии подряд с 1 | `DUPLICATE_ID`, `SCHEMA_DEF_INVALID` |
| версия записана строго позже предыдущей; ссылка — на определение, записанное не позже неё | `TEMPORAL_ORDER_INVALID` |
| запись журнала = единственное допустимое отличие от предыдущей версии | `SCHEMA_CHANGE_INVALID` (новый) |
| родитель/класс связи/тип идентификатора атрибута существует в том же tenant | `REF_UNRESOLVED` |
| корень наследника = корню родителя; нет цикла; родитель и классы связи не выведены из употребления; атрибут не повторяется; у предиката один определитель; симметричная связь — в одном классе; одна схема и один приоритет на корневой тип; формат корректен | `SCHEMA_DEF_INVALID` (новый) |
| маркировка наследника, связи, утверждения не шире маркировки того, на что они опираются | `MARKING_BROADER_THAN_INPUT` |
| `schema.is_a`: класс действует на момент записи; не абстрактный и не выведен из употребления | `REF_UNRESOLVED`, `TEMPORAL_ORDER_INVALID`, `CLASS_NOT_INSTANTIABLE` (новый) |
| `schema.is_a`: корень класса = тип сущности | `PREDICATE_DOMAIN_VIOLATION` |
| предикат `x.…` действует в схеме tenant на момент записи | `PREDICATE_UNKNOWN` |
| субъект — экземпляр класса; значение/объект — объявленного вида | `PREDICATE_DOMAIN_VIOLATION`, `PREDICATE_RANGE_VIOLATION` |
| у предиката tenant нет квалификаторов и измерений Проверки | `QUALIFIER_INVALID`, `CHECK_CLAIM_DIMENSION_MISMATCH` |
| значение идентификатора схемы tenant — по её формату, для корневого типа субъекта | `IDENTIFIER_SCHEME_INVALID` (новый) |
| значение встроенной схемы — контрольные цифры, при любом предикате | `IDENTIFIER_CHECKSUM_INVALID` |
| у экземпляра нет обязательного атрибута действующей схемы | предупреждение `REQUIRED_ATTRIBUTE_MISSING` (новое) |
| два значения атрибута с кардинальностью ONE | предупреждение `CONTRADICTION_SINGLE_VALUED` |

Каждое правило имеет негативный вектор и мутанта, которого этот вектор убивает (правило проекта); 129 векторов
цикла 9 (`N9xx`/`P9xx`), 98 мутантов (`M900`–`M997`).

## 4. Срез (`slice/ddl_s9.sql`, применяется после `ddl_s5b.sql`)

- `ac.class_defs`, `ac.link_defs`, `ac.identifier_defs` — версии определений, только INSERT; форма полей проверяется
  ограничениями (маркировка, непустые имена, атрибуты, формат), остальное — стражами с теми же кодами, что у валидатора.
- `ac.class_closure` (замыкание иерархии, строится при вставке класса: 1000 классов — 1 с, цепочка глубиной 400 —
  1,2 с) и `ac.schema_predicates` (владелец предиката) — пишут только триггеры `SECURITY DEFINER`; прямые INSERT,
  UPDATE, DELETE запрещены всем ролям, включая владельца.
- `ac.claims_schema` — страж утверждений: предикат вне реестра и вне схемы; `schema.is_a`; предикаты `x.…`;
  идентификаторы схем tenant; пометка версии записи. Запись утверждения и изменение схемы tenant не пересекаются
  (разделяемая и исключительная блокировка `schema:tenant`); отзыв принадлежности не пересекается с записью
  утверждения, которое на неё опирается (блокировка `claim:`).
- `ac.schema_journal` — журнал: каждая версия каждого определения.
- Проекции (читатель — только `EXECUTE`, допуск по `session_user`): **`ac.model(project, as_of)`** — классы с
  собственными и унаследованными атрибутами, связи, типы идентификаторов, журнал на момент `as_of`; определения с
  маркировкой выше допуска не видны ни сами, ни через атрибуты наследника; ответ на прошлый момент воспроизводим
  (тот же digest). **`ac.schema_gaps(project, as_of)`** — незаполненные обязательные атрибуты. Досье: «Синий кит:
  класс — «Вид китов».», «Синий кит: наибольшая длина — 30 м.» — названия берутся из схемы на запрошенный момент.
- Загрузка: `slice/schema_s9.py` (записи → SQL; живая запись под `ac_modeler`), `slice/load_s1.py` (исторический
  импорт: схема → утверждения `schema.is_a` и их рецензии → остальные утверждения).

## 5. Конструктор модели (`core/model_constructor.py`)

Команды: `init`, `add-class`, `add-attribute`, `change-attribute`, `remove-attribute`, `add-link`, `add-identifier`,
`set-strength`, `rename`, `deprecate`, `show` (схема на момент, с наследованием), `journal`, `validate`. Каждая
правящая команда добавляет одну версию одного определения, прогоняет весь набор через нормативный валидатор и пишет
файл только при отсутствии ошибок; отказ оставляет файл нетронутым. Приёмка T9: 11 команд принято, 12 отказов.

## 7. История проверки S9

**Раунд 1 — ВОЗВРАТ.** Первая сдача цикла (сессия до этой) объявила цикл завершённым без независимой рецензии и без
единого применения DDL к базе. Рецензент нашёл 28 дефектов: DDL не применялся (зарезервированное слово), страж
`schema.is_a` отвергал всё, на новые таблицы не было прав, база принимала произвольные маркировки и время,
идентификаторы схемы были глобальными (утечка между tenant), маркировка класса не учитывалась, атрибуты, версии,
`LinkDef`, `IdentifierDef`, `is_abstract` ничего не решали, 7 правил были без убивающего вектора, CLI падал на любом
входе. Кроме того, набор репозитория содержал устаревшую схему, а четыре коммита не были отправлены в GitHub, хотя
handoff v008 утверждал обратное. Цикл переделан целиком (§2–§5).

**Раунд 2 — ПРИНЯТО С ЗАМЕЧАНИЯМИ** (тот же рецензент, новый снимок): из 28 замечаний 24 закрыты, 3 закрыты частично
с явным переносом (§8), 1 — с остатком. Новых замечаний 7, все исправлены:
