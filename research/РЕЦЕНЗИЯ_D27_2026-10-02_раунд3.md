## Новые замечания (все P2)

**M-01 · D27.3 против D27.4.** Ленивая материализация создаёт «утверждение-запись D2» — литерал — вся строка, а `ROW` цитирует *одну* колонку, и страж требует равенства литерала цитате. Одно исключает другое. Заодно утверждение-запись ЕГРЮЛ несёт руководителя, то есть PERSONAL_DATA по максимуму. Дописать: `ROW` цитирует набор колонок, маркировка — максимум по процитированным; утверждение-запись включает только колонки до заданной маркировки.

**M-02 · D27.4.** Хэш колонки = sha256(имя, значение) без соли. Соседние хэши из `merkle_path` для колонок с малым числом значений (ИНН руководителя, фамилия из словаря) подбираются перебором — утечка закрытой колонки через путь. Добавить соль на строку/колонку, хранимую в файле.

**M-03 · D27.6 против D27.4.** Функция поиска шлюза читает допуски и обслуживает читателей, а `ac_gateway` — «член `ac_storage` и ничего больше». Нужна отдельная роль/служба поиска.

**M-04 · устаревший текст.**
- D27.3: «≈5–6 КБ на строку, ЕГРЮЛ ≈45 ГБ, 100 млн ≈0,6 ТБ» — по новому .out 4225–4395 Б, 31,5–32,7 ГБ, ≈0,43 ТБ.
- §0: «открытых вопросов — семь» — в §8 их восемь.
- §0 п. 3: «детерминированна по идентификатору (ИНН/ОГРН/телефон…)» — телефон убрать (противоречит D27.3).
- §6, цикл 9: «миграции через новые утверждения + `WITHDRAWN`» — по D27.1 теперь по умолчанию при чтении.
- D27.1: «класс на момент t — по `recorded_at`», а схема — по `ingested_at`; привести к одному системному времени.
- §3: «JSONB — 1,5–1,7 мс» — в .out 1,64–1,69.
