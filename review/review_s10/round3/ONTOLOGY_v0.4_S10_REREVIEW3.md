## 2. Что атаковано в новом и устояло

**Запрет уровней, кроме `READ COMMITTED`.**
- Смешанные пары SERIALIZABLE ↔ READ COMMITTED (обход прошлой версии снимка, M1–M4): сериализуемая транзакция отвергнута `ISOLATION_LEVEL_UNSUPPORTED`, итог согласован во всех четырёх.
- REPEATABLE READ с подтранзакцией, с `SET CONSTRAINTS ALL IMMEDIATE`, с `ac.historical_import`: отказ.
- Смена уровня после первого запроса (`SET TRANSACTION`, `SET LOCAL transaction_isolation`): отказ самого PostgreSQL.
- `READ ONLY DEFERRABLE`: запись невозможна. DO-блок в SERIALIZABLE: отказ. Запись каталога через `SECURITY DEFINER`-триггер в REPEATABLE READ: отказ.
- Три одновременные транзакции READ COMMITTED (две версии с `previous = P` и документ `P`): отвергнут документ, в базе 0 документов и 2 версии — согласовано.
- Подготовленные транзакции в этом кластере выключены (`max_prepared_transactions = 0`); при включённых поведение не проверено.
- Законные сценарии прежних срезов запретом не сломаны: вся регрессия PASS (раздел 4).

**Единственность ключа.** Набор без ключа с повторённой строкой: валидатор (файл в хранилище) — «ключ строки повторяется в версии набора»; печать — `DATASET_LOAD_INVALID: строка повторяется`.

**Производный секрет.** Секретов на 5 строк — 5; один ключ набора в другом наборе с теми же строками даёт другие секреты; перестановка значений между колонками даёт другой секрет.

**`dataset_file_error`:** 20 000 строк в одном файле — 2,3 с.
