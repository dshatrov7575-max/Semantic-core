## 3. Новые находки

### S23-01 (P0, проекции/срез) — отчёт закрытой Проверки меняется после закрытия её предыдущей Проверки
Скрипт: `attacks/s23_previous_open.py` (ac_loader). Проверка `chk_closed_k2` закрыта (COMPLETED) со ссылкой на ОТКРЫТУЮ `chk_prev_open`;
позже `chk_prev_open` завершается с риском MEDIUM. `check_report` берёт `pv.*` текущими, а не на момент `t`.
Наблюдалось:
```
before: previous {'as_of': '2026-09-29', 'profile': 'EXPRESS_NEGATIVE', 'check_id': 'chk_prev_open'} sha256:3979545f…
after:  previous {…, 'overall_risk': 'MEDIUM'}                                                 sha256:0651c44e…
```
Исправление: закрывать Проверку только при предыдущей COMPLETED с `completed_at ≤ t` (валидатор + `checks_guard`), а `previous` в отчёте строить на момент `t`.

### S23-01v (P1, онтология) — валидатор принимает то же
`attacks/s23_01_validator.py`: эталонный мир, `chk_express_1` переведена в IN_PROGRESS, `chk_full_1` (COMPLETED) ссылается на неё → `errors: []`.
Исправление: правило «предыдущая Проверка закрытой Проверки — COMPLETED раньше неё» + негативный вектор + мутант.

### S23-02 (P0, срез) — ac_migrator после печати меняет отчёт закрытой Проверки через наблюдения источника
`attacks/s23_observation_backdate.py`. Источник впервые наблюдён после печати; Проверка с утверждением по нему закрыта (живьём);
ac_migrator в историческом режиме добавляет наблюдение с `observed_at` = печать + 1 с. `evidence_json.first_observed_at = min(observed_at)` меняется.
```
first_observed_at before: 2026-09-30T22:17:20.658743Z  sha256:ff05a542…
first_observed_at after:  2026-09-30T22:17:19.098882Z  sha256:b63f6c58…
```
Исправление: в `observation_guard` запрещать историческое `observed_at` ≤ закрытия любой закрытой Проверки, цитирующей источник (как в `reviews_guard`), либо брать в отчёт наблюдения с `ingested_at ≤ t`.

### S23-10 (P0, срез) — гонки: правила S22-02/04/05 проверяются по зафиксированному состоянию без блокировок
Системное время = начало транзакции (`now()`), охранники читают только зафиксированные строки, блокировок нет. Три варианта, все живыми ролями ac_loader, без исторического режима:
- **S23-10** `attacks/s23_race_review.py`: T2 вставляет REFUTED по утверждению X (recorded_at = t0) и держит транзакцию; T1 (t1 > t0) закрывает Проверку с X (для T1 X — ACCEPTED); T1, затем T2 фиксируются.
  ```
  claim status in the closed report before/after: ['ACCEPTED'] ['REFUTED']
  completed_at=01:21:43.456 review recorded_at=01:21:41.954 status_at(X, completed_at)=REFUTED
  digest f3b9c816… -> 5df22c09…
  ```
  Нарушен и инвариант CHECK_CLAIM_NOT_ACCEPTED_AT_COMPLETION.
- **S23-10b** `attacks/s23_race_merge.py`: T2 сливает объект утверждения (`status_changed_at` = t0) и держит; T1 закрывает Проверку; имя в закрытом отчёте: «Участок 50:12:0101001:245» → «НОВОЕ ИМЯ УЧАСТКА» (обход S22-02).
- **S23-10c** `attacks/s23_race_rows.py`: T2 вставляет след поиска в открытую Проверку и держит; T1 закрывает; после фиксации T2 в закрытом отчёте: `['ИНН'] → ['ИНН', 'ПОДБРОШЕННЫЙ ПОИСК']` (обход closed_xact, S22-04/05).

Исправление: сериализовать по объекту — `pg_advisory_xact_lock` по claim_id в `reviews_guard` и `check_claims_guard`, по check_id (или `SELECT … FOR SHARE` строки Проверки) в охранниках строк Проверки и в `checks_guard`, по entity_id в слиянии и при закрытии; либо `default_transaction_isolation = serializable` для ac_loader/ac_migrator.

### S23-13 (P0, срез) — ac_app получает право исторического импорта (обход RS-11)
`attacks/s23_historical_escalation.py`. `ac.historical()` проверяет `pg_has_role(current_user, 'ac_migrator')`; внутри SECURITY DEFINER-триггеров
`entities_guard`, `checks_guard`, `identity_decisions_guard` (владелец — суперпользователь postgres) `current_user = postgres` → всегда true.
ac_app (не член ac_migrator: `pg_has_role = f`) делает `SET LOCAL ac.historical_import = 'on'` и пишет время задним числом:
```
entity:  created_at 01:27:11.97, status_changed_at 01:27:12.47, now 01:27:15.04
check :  requested_at 01:27:35.49, completed_at 01:27:36.49, now 01:27:38.19   (COMPLETED, вставлена ac_app)
control (claim_reviews, INVOKER-триггер): recorded_at = системное время (исторический режим НЕ сработал)
```
Следствие: приложение закрывает Проверки «в прошлом» (например, до рецензии, опровергшей утверждение), датирует слияния и решения.
Исправление: вычислять `ac.historical()` в INVOKER-коде (отдельный BEFORE-триггер или INVOKER-обёртка для времени), а SECURITY DEFINER оставить только для записи ключей; владелец триггерных функций — не суперпользователь.

### S23-03 (P1, проекции/срез) — отменённая Проверка выглядит завершённой
`attacks/s23_check_text.py`. В транзакции отмены ac_loader пишет итог FOUND/HIGH на ОСПОРЕННОМ утверждении и NOT_FOUND со следом поиска,
выполненного за 400 дней до запроса. Отчёт CANCELLED: `draft` нет, риск HIGH, «Не выявлено.»:
```
status CANCELLED draft None | TENDERS HIGH … DISPUTED | NEGATIVE text: Не выявлено. search performed_at 2025-08-26T22:18
```
Исправление: у CANCELLED не выводить результаты/риски (или помечать «Проверка отменена, итоги недействительны»); итоги в отменяемую Проверку не принимать.

### S23-04 (P1, проекции) — черновик отчёта выдаёт опровергнутое утверждение как факт

Исправление: в `check_report` исключать REFUTED/WITHDRAWN на момент `t` (как в досье) или помечать их в тексте.

### S23-11 (P2) — текст ПРИМЕР_ДОСЬЕ_S3.md / ПРИМЕР_ОТЧЁТА_S3.md против правил владельца
